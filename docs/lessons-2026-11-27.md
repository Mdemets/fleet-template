# Lessons from the 2026-11-27 session

A retrospective over one long session: what broke, what the evidence was, and what rule or habit came
out of it. Every entry names the evidence, because a lesson without its measurement is folklore.

Rules R1-R3 were adopted by the operator during the session. R4-R5 are drafted from this review and
await adoption; an agent may draft a rule, only the human adopts one.

## Rules that came out of it

| Rule | Content | Status |
|---|---|---|
| R1 | The coordinator owns project files; changes are proposed in `proposals/`, not applied | adopted |
| R2 | Instruction updates are handled sequentially; new input does not dismiss an earlier request | adopted |
| R3 | Every rule and behaviour change reaches this template in the same pass it is adopted | adopted |
| R4 | Before any restart or reboot, name the recovery path; a headless reboot without out-of-band access is a physical intervention | drafted |
| R5 | A bundle is only durable when it exists off the machine that produced it; copy out in the same pass and compare tips | drafted |

## Lessons, each with its evidence

### L1 - Appending a line to a config file puts it wherever the file ends

A `ListenAddress` line appended to `sshd_config` landed inside the trailing `Match Group administrators`
block. sshd refused to load: *"Directive 'ListenAddress' is not allowed within a Match block"*. That
single line caused hours of crash-looping that was then misattributed to the binary.
**Habit:** validate with the tool's own parser (`sshd -T`) before restarting anything, and place
directives in a section, not at the end of a file.

### L2 - A script that stops early leaves its later effects undone

The bootstrap script aborted at `Start-Service` (step 2 of 6) and never reached the key install (step
5). A later report said "fleet key: present" because it checked that the *file* existed, not what was in
it. The key was absent the whole time.
**Habit:** verify the artifact, not the attempt. Exit codes describe what a script tried.

### L3 - Rotating a credential file does not rotate a running process

A worker read its share password once at startup and held it in memory. Rekeying the file left the live
process authenticating with a dead password, which retried every ~36 s and locked the account. The file
was correct and a fresh `net use` proved it, which is exactly why the check was misleading.
**Habit:** stop the service **and** kill the process before rekeying; verify from the process's context,
not from a new session.

### L4 - Retry loops turn one bad credential into an outage

Lockout policy was 10 attempts / 10 minutes; the worker retried every 36 s and held the account locked
long after the cause was fixable. Testing the fix required waiting out the lockout.
**Habit:** fail fast on authentication errors (86, 1326, 1909) and cool down on everything else. A
credential that is wrong will not become right by asking again.

### L5 - Move preserves timestamps, so "age of claim" was really "age of task"

The reaper aged a claim by the file's `LastWriteTime`, but `Move-Item` inside the share preserves it from
the queue file. Measured: a file backdated three hours stayed three hours old after the move, so a
backlogged task looked stale the instant it was claimed and was requeued while still running.
**Habit:** stamp the claim explicitly. And stamp it somewhere the writer can actually write - the worker
could rename into `claimed/` but not modify the file (`Access is denied`), so the claim time went into
`results/<node>/claims/<id>.json` instead.

### L6 - A test that passes with the bug restored is not evidence

Twice in one session. First, a regression test passed with the defect reintroduced because it exercised
the wrong case (`Some(&None)` falls through; only an *unset* lock diverged). Second, the proposed fix
was explained wrongly until the mutation exposed it. A green test with the bug present is worse than no
test: it certifies a false explanation.
**Habit:** break the fix deliberately, watch the test go red, restore, then claim it works.

### L7 - Absence must be reported as unknown, never as health

The first audit reported "fleet stalled" because the queue was empty and worker logs were stale. Work
was flowing through agent lanes; the queue was simply a different transport. The same shape appeared
again with `audit.jsonl`: the claim "no script writes it" was false, and the file was absent only because
nothing had finished.
**Habit:** an idle component is not an idle system, and a missing file is not a missing producer. Read
the code before asserting that something does not exist.

### L8 - Instrument builds are gated by features, not profiles

`--profile diag` did not enable frame capture; the gate is the cargo **feature** `diagnostics`.
`cargo build --profile diag -p victory --features diagnostics`. Related: cargo cannot replace an exe
that is running (`Access is denied`), so stop the title before rebuilding.
**Habit:** when an instrument produces nothing, check that it was compiled in before doubting the
measurement.

### L9 - Windows blocks write-up across integrity levels

Directories created from a High-integrity session (SSH) are owned by Administrators and carry a high
label; a Medium-integrity desktop session cannot write into them. The failure is a bare
`Access is denied (os error 5)` on a folder whose `icacls` looks fine.
**Habit:** create files in the same session that will use them, and do not move a path to fix a
permission error before identifying which session created it.

### L10 - A waiting screen looks exactly like a deadlock

Three times. The distinguishing evidence: the **present counter** stalls while the **fps report keeps
firing**. A hung process stops both. The title additionally holds a five-second timer on its disclaimer
that ignores keys, which is indistinguishable from a hang in a trace.
**Habit:** record the input route and the trace signature of each screen; treat a frozen counter with a
live fps line as waiting.

### L11 - Durability means off the machine that produced it

The bundle containing the four lane merges was written only to the coordinator. The coordinator then
went down, and the off-site copy was four merges stale. Recovery worked only because the lane branches
were inside the older bundle.
**Habit (R5):** write the bundle and the off-site copy in the same pass, and compare tips rather than
assuming.

### L12 - A headless reboot without out-of-band access is a physical intervention

The coordinator was rebooted to repair a damaged WMI provider and never returned to the network. No
IPMI, no console: recovery waits for a human to walk to the machine. The proposal had named no way back
if the box stayed down.
**Habit (R4):** before any restart, name the recovery path. If there is none, the decision belongs to
the operator.

### L13 - Documentation has to live where the subject reads it

The auditor's role was written into a repository the coordinator never reads. The coordinator could see
its files changing and had no way to know why, which is exactly what an audit should prevent.
**Habit:** the record goes where the thing being changed looks first - the share, the README, the change
log.

### L14 - Network topology decides what can be taken over

An attempt to make the operator PC a fallback coordinator failed: the VPN is client-to-server, so the
LAN cannot reach the client (`172.16.0.6:445` unreachable even with a subnet-scoped firewall rule). The
setup was built, tested and torn down.
**Habit:** verify the path with a listener before building a service end; elevation does not create
routing.

### L15 - A worker cannot authenticate to a share on its own machine

Windows' SMB loopback check rejects it. When a worker was promoted to coordinator, its own worker had to
be disabled rather than coaxed.
**Habit:** promote a node to coordinator-only; do not leave it as both.

### L16 - Measure the symptom, not the story about it

"Black screen" was interpreted for hours. A captured PNG with `RGB(0,0,0) A=255` at four frames settled
in one step that the renderer - not the display path - was producing black. Later, a render-target dump
showed the intermediate target is a *single flat colour*, which overturned the previous hypothesis about
textures sampling zero.
**Habit:** convert descriptions into files. A pixel value outlives a screenshot and beats an adjective.

## The pattern behind most of these

Nearly every failure came from trusting a proxy instead of the thing: a file instead of the process, an
exit code instead of the artifact, a queue instead of the work, a green test instead of a red one, a
description instead of a pixel. The rules above are all one idea wearing different clothes - measure the
thing itself, and when you cannot, say so instead of substituting something convenient.

## Second pass, same day: the transport work

These came out of building parallel workers, and each cost more than the first set.

### L17 - A child process does not inherit its parent's network session

Three designs assumed it: UNC slots spawned by a supervisor, drive-letter slots under a dedicated
service account, and pooled slots under SYSTEM. All three started, logged their start line, and then
hung before their first heartbeat with no error. Runspaces inside one agent process work because they
share that process and its session.

**Habit:** when a spawned worker cannot see a network path its parent can, do not debug the path -
stop spawning and parallelise inside the process.

### L18 - A `continue` on a permission failure is a silent worker

Claim markers were created next to the task in `queue/`, which the worker account cannot write. The
create threw, the catch did `continue`, and 32 slots ran for hours claiming nothing. No error line,
no heartbeat change, no queue movement: the most dangerous state a worker can be in, because it looks
identical to an idle fleet.

**Habit:** any `catch { continue }` in a loop needs a throttled log line at minimum. Silence is not a
success path.

### L19 - Check per-node distribution, not the drained count

Three times the coordinator covered for broken workers: 300 tasks drained, 300 done by one machine. A
burst that reports "drained N/N" certifies a fleet that is not working.

**Habit:** every throughput measurement reports results grouped by node. A node at zero while its agent
runs is the fault signature.

### L20 - Cleanup must include the claims

Test cleanup deleted results but left claim files. The reaper then did exactly its job: it saw claims
with no results and requeued 58 completed tasks. The bug was in the cleanup, not the reaper.

**Habit:** a test that removes its artefacts removes the claim, the result and the queue entry, or it
is manufactured work for the reaper.

### L21 - Shell layers eat backslashes and quotes

A UNC written through SSH arrived as one backslash and the agent reported `The network name cannot be
found`. An `-Accounts` list arrived comma-joined and was resolved as a single account name, throwing
`IdentityNotMapped`. A remote path was interpolated inside single quotes and treated literally.

**Habit:** build paths from character codes (`[char]92`) when they cross a shell boundary, split list
parameters on commas defensively, and prefer a script file over a nested one-liner every time.

### The through-line of the second pass

Every failure was silent and every success was measured. The fleet did not break loudly; it stopped
contributing, and only per-node numbers showed it. That is the same lesson as the first pass wearing
different clothes: measure the thing itself, and when you cannot, say so.
